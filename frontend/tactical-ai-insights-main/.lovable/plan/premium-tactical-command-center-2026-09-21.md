# Premium Tactical Command Center

## Goal
Build a polished, responsive football-analysis frontend using the supplied project and university logos, realistic clearly labelled placeholders, and scientific-safety states that never imply unsupported results.

## Experience
- Create a shared dark command-center shell with desktop navigation, compact mobile navigation, project branding, and restrained university attribution.
- Build distinct routes for Dashboard, New Analysis, Processing, Results, Comparisons, Validated Showcase, and Research / Methodology.
- Add subtle pitch-grid, scanning, trajectory, node, processing, glow, and transition motion with reduced-motion support.
- Use a navy/near-black, football-green, cyan, and high-contrast neutral design system with thin luminous borders and controlled glass effects.

## Key screens
- Dashboard: branded statement, animated tactical pitch, action links, and placeholder system cards.
- New Analysis: four-step workflow, real local file selection metadata, coach-audio choices, methodology selection, calibration safeguards, and a review summary. No fake submission or backend success state.
- Processing: asynchronous-ready progress presentation, session context, pipeline states, elapsed-time placeholder, and tactical visualization.
- Results: safe sample states, responsive metrics, six tabs, unavailable-metric reasons, withheld player analysis, report, and technical metadata.
- Comparisons: evidence-only whole-system and controlled-identity comparisons without winners or invented claims.
- Validated Showcase: three explicitly oracle-assisted demonstration cases with frozen placeholder media and the required disclaimer.
- Research / Methodology: academic context, methodology summaries, reliability-gate definitions, and university attribution.

## Technical approach
- Keep typed domain models and mock presentation data separate from route UI, ready for later API integration.
- Build small reusable components for navigation, tactical pitch visuals, status badges, metric displays, methodology cards, tabs, and limitation panels.
- Store uploaded official SVGs as immutable app assets and make a separate padded favicon copy from the project logo.
- Add unique metadata for every content route.
- Validate compilation and inspect desktop and mobile layouts in the running preview.

## Boundaries
- No AI inference, backend, storage, Modal, database connection, or fabricated scientific findings.
- All sample values and media are visibly labelled as placeholders or demonstration-only.
- Failed identity gates render as completed-with-limitations states, not application failures.
